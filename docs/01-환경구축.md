# 01. 환경 구축

## 목표
탐지 서버와 감시 대상 서버를 분리한 2대 구성의 실습 환경을 만든다.
감시 대상을 따로 두는 이유는, 이후 공격 시나리오를 발생시킬 때
공격자 프로세스가 대상 서버의 자원 지표를 오염시키지 않도록 하기 위함이다.

## 호스트 환경
- Windows 11, RAM 16GB
- VMware Workstation Pro 17.6.3

## VM 구성
| 구분 | 역할 | OS | IP | RAM |
|---|---|---|---|---|
| VM1 | 탐지 서버 (Zabbix Server, MariaDB, Python) | Ubuntu 24.04.5 Desktop | 192.168.199.10 | 6GB |
| VM2 | 감시 대상 서버 (Zabbix Agent) | Ubuntu 24.04 Server | 192.168.199.20 | 2GB |

- 네트워크: VMware NAT (192.168.199.0/24), 게이트웨이 192.168.199.2
- DHCP 대역과 겹치지 않도록 .10 / .20 을 고정 IP로 할당

## 트러블슈팅: VMware 설치 시 Hyper-V 충돌

### 증상
VMware 설치 중 "host has Hyper-V or Device/Credential Guard enabled" 경고가 발생했다.
Windows 기능에서 Hyper-V, 가상 머신 플랫폼, Windows 하이퍼바이저 플랫폼,
Windows 샌드박스를 모두 해제하고 메모리 무결성도 껐으나 경고가 계속 나타났다.

### 원인 확인
msinfo32 로 확인한 결과 "가상화 기반 보안: 실행 중" 상태였다.
Hyper-V 기능을 해제해도 VBS(가상화 기반 보안)는 별도로 동작하고 있었고,
이것이 하이퍼바이저를 점유하고 있어 VMware가 자체 하이퍼바이저를 사용하지 못하는 상태였다.
또한 bcdedit 출력에 hypervisorlaunchtype 항목이 없어,
앞서 실행한 설정이 관리자 권한 부족으로 적용되지 않았음을 확인했다.

### 조치
관리자 권한 환경에서 아래를 적용 후 재부팅했다.

    bcdedit /set hypervisorlaunchtype off
    reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard" /v EnableVirtualizationBasedSecurity /t REG_DWORD /d 0 /f
    reg add "HKLM\SYSTEM\CurrentControlSet\Control\LSA" /v LsaCfgFlags /t REG_DWORD /d 0 /f
    reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 0 /f

### 배운 점
화면에 보이는 설정(Windows 기능, 메모리 무결성)을 모두 껐다는 것이
실제로 기능이 비활성화되었다는 뜻은 아니었다.
msinfo32 와 bcdedit 으로 현재 상태를 직접 확인한 뒤에야
설정이 적용되지 않았다는 사실과 남아 있는 원인을 특정할 수 있었다.

## 결과
- VM1 설치 및 고정 IP 설정 완료
- SSH 서버 구성, 호스트에서 원격 접속 확인
- 스냅샷 base-ssh-ok 생성
