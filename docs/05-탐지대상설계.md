# 05. 탐지 대상 공격 설계

## 배경
탐지 시스템을 만들기 전에, 무엇을 탐지할 것인지를 먼저 정의했다.
탐지 대상이 정해져야 그 공격이 남기는 흔적을 알 수 있고,
어떤 지표를 수집해야 하는지도 역으로 결정되기 때문이다.

## 탐지 대상 공격 5종
성격이 서로 다른 공격을 선정해, 자원 지표와 로그 지표를
모두 활용해야 탐지가 가능하도록 구성했다.

| 공격 | 남기는 흔적 | 관련 지표 |
|---|---|---|
| SSH 무차별 대입 | 로그인 실패 급증, 성공은 없음 | 로그인 실패/성공 수 |
| 포트 스캔 | 짧은 시간에 다수 포트로 연결 시도 | TCP 연결 수, SYN-RECV 수 |
| 웹 요청 폭주(DoS) | 요청·CPU·네트워크 동시 급증 | CPU, 네트워크 수신 |
| 악성 프로세스(채굴형) | 로그인·네트워크는 정상, CPU만 지속적으로 높음 | CPU, 메모리 |
| 데이터 유출 | DB 반출 시 네트워크 송신량 급증 | 네트워크 송신 |

## 설계 의도
단순히 부하를 일으키는 공격(DoS)만 대상으로 하면
고정 임계값(예: CPU 80% 초과)만으로도 탐지가 가능해
이상 탐지 모델을 적용할 근거가 약해진다.

특히 채굴형 악성 프로세스는 로그인, 네트워크 등 다른 지표는 모두 정상이고
CPU만 높은 상태이기 때문에, 여러 지표를 함께 보지 않으면
정상적인 부하 증가와 구분하기 어렵다.
이처럼 단일 지표로 판단할 수 없는 공격을 포함시켜,
이상 탐지 모델을 사용할 필요가 있는 문제로 설계했다.

## 구성상 제약
자원 한계로 VM1이 탐지 서버, 정상 트래픽 생성, 공격 발생을 모두 겸했다.
공격은 폐쇄망(192.168.199.0/24) 내부에서 VM1 → VM2 방향으로만 수행하며,
외부로 향하는 트래픽은 발생시키지 않는다.

## 수집 지표 정리
위 공격들을 탐지하기 위해 다음 지표를 수집하도록 구성했다.

- CPU 사용률
- 메모리 사용량
- 네트워크 수신 / 송신
- 로그인 실패 수 / 성공 수 (UserParameter)
- TCP 연결 수 / SYN-RECV 수 (UserParameter)
