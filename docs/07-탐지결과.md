# 07. 탐지 결과

> 하이브리드 IDS(Isolation Forest 모델 + 룰)로 공격 6종을 실제 발생시켜
> 탐지 여부를 검증한 결과를 정리한다. (측정일 2026-10-07, 재검증 10-08)

## 1. 요약
- 공격 **6종 전부 탐지(미탐 0)**, 오탐은 튜닝 후 사실상 0.
- 자원을 여러 지표로 흔드는 공격(DoS·채굴)은 **모델**이, 단일 지표/로그에만
  흔적이 남는 공격(무차별 대입·대역폭 유출)은 **룰**이 잡았다.
- 최종 등급 = 모델·룰 결과 중 더 심각한 쪽.

## 3. 공격별 상세

### 3-1. DoS 웹 과부하 — 모델 탐지
- ab로 app.php에 과도한 동시 요청 → 연결 수(conn)와 CPU가 폭증.
- 14:15~15:00 구간 모델 [위험], 최저 score **-0.088**(전 구간 최저).
- 기여 Feature: conn_max(+354σ), conn_std(+315σ), conn_mean(+243σ).
- → 여러 지표가 동시에 크게 흔들려 모델이 강하게 반응.

### 3-2. 채굴형 CPU 지속 — 모델 탐지
- stress-ng --cpu 2로 두 코어를 45분간 포화.
- 15:40~16:00 [위험](최저 -0.067), 기여 cpu_user_std(+111σ)·max(+77σ).
- **발견**: 모델이 가장 강하게 반응한 건 CPU가 급등하는 과도기(std 큼)였고,
  CPU가 88%에 일정하게 고정(std≈0, 16:05~)되자 [경고]로 약화.
  → Isolation Forest가 절대 수준(mean)보다 변동성(std)·순간최대(max)에 민감.
  → 느리게 램프업해 일정하게 유지하는 은밀한 채굴은 탐지가 약해질 수 있음(과제).

### 3-3. 데이터 유출 — 모델 미탐 → 룰로 해결
- VM2→VM1로 /dev/zero를 nc로 ~46MB/s 지속 전송(net_out 평소의 ~200배).
- 모델: net_out_std/max/mean이 +400~600σ였는데도 최종 **[정상](+0.03)으로 미탐**.
  - 원인: Isolation Forest는 32개 Feature의 평균 고립도로 점수를 내므로,
    단일 지표(net_out) 하나만 극단적이고 나머지 29개가 정상이면 신호가 희석됨.
    (무차별 대입이 ssh_fail만 튀어 미탐됐던 것과 동일한 현상)
- 해결: net_out_mean ≥ 50MB → [위험] 룰 추가(정상 상한 ~17MB와 분리).
  재검증 시 net_out 평균 291MB로 **[위험] 정확히 탐지**.

### 3-4. SSH 무차별 대입 — 룰 탐지(모델은 미탐)
- hydra로 SSH 로그인 반복 실패 유발.
- 모델은 ssh_fail만 튀고 자원은 정상이라 미탐 → 룰(ssh_fail≥30 & ssh_ok<1 → 위험)이 포착.
- v1은 4분으로 짧아 30분 창에 희석돼 경고(ssh_fail 평균 20), v2·v3는 위험.

## 4. 종합
- "자원이냐 로그냐"가 아니라 **"여러 지표가 동시에 흔들리는 공격(모델이 강함) vs
  단일 지표만 튀는 공격(모델이 약함)"** 이 본질적 경계였다.
- 단일 지표형(무차별 대입·대역폭 유출)은 명시적 룰로 보완 → **하이브리드 설계가
  로그/자원 양쪽의 단일 지표 공격 모두에서 입증**됨.
- 상세 성능 수치와 튜닝 과정은 [08-튜닝.md] 참고.
